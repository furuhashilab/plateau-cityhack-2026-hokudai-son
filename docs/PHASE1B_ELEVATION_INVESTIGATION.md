# Phase 1B Elevation Investigation

## Decision

Use GSI DEM5A elevation PNG tiles for the Phase 1B numeric ground-elevation dataset and lowland colors. Keep the Phase 1A ellipsoid globe rather than adding streamed terrain in this phase.

Reasons:

- approximately 5 m source grid is sufficient for the simplified `max(0, tideLevel - groundElevation)` MVP
- official, nationwide, browser-friendly RGB PNG tiles
- orthometric heights can be decoded once into a reusable numeric grid
- nine z15 tiles cover the initial West Maizuru demo AOI with bounded network, CPU, GPU, and heap cost
- no new dependency, server, token, paid service, or preprocessing pipeline
- avoids the additional runtime cost and availability dependency of streamed quantized-mesh terrain

The runtime AOI is GSI z15 XYZ x=28701–28703, y=12927–12929. It is deliberately a demo extract, not all of Maizuru.

For the selected nine-tile AOI, 492,122 valid DEM5A samples were measured:

- minimum: -0.10 m
- 10th percentile: 1.34 m
- 25th percentile: 3.90 m
- median: 25.71 m
- 75th percentile: 84.32 m
- 90th percentile: 159.30 m
- maximum: 301.46 m

Selected bands:

- below 2 m: 17.9%
- 2–5 m: 11.0%
- 5–10 m: 7.9%
- 10 m and above: 63.2%

These thresholds are retained because they distinguish the coastal lowland classes relevant to later storm-surge explanation while grouping the surrounding steep high ground into one contextual class. Negative source samples are included in “Below 2 m”; they are not silently clamped.

## Height reference investigation

The involved heights are different quantities:

```text
ellipsoid height h = orthometric height H + geoid height N
```

- GSI DEM elevation is orthometric height above the mean-sea-level reference.
- Cesium Cartesian positions and geocentric 3D Tiles use WGS84 ellipsoid height.
- PLATEAU 3D Tiles are normally converted to EPSG:4979 / ellipsoid height for Cesium use.
- PLATEAU-Terrain likewise converts orthometric DEM to ellipsoid height by adding a fixed Japanese geoid model.
- Around Japan, geoid height is commonly roughly +30 to +45 m; the exact value must come from an appropriate geoid model, not from the visual `-36 m` workaround.

Official PLATEAU-Terrain height explanation and endpoint:

- <https://docs.plateauview.mlit.go.jp/datasets/terrain/>

### Historical `heightOffsetMeters: -36` decision

**This is retained for the presentation MVP as a visual alignment workaround.**

The selected visualization does not replace Cesium's ellipsoid globe with an elevation terrain surface. Therefore removing `-36 m` would again leave ellipsoid-height PLATEAU buildings visibly above the zero-height ellipsoid surface. The offset is not applied to GSI DEM values, is not used by the future flood formula, and is not accepted as the measured Maizuru geoid height.

If PLATEAU-Terrain is enabled later, both terrain and buildings are in ellipsoid height and the correct expected building offset is 0 m. That change must be visually and numerically tested at representative control points before removing the workaround.

Presentation MVP terrain rollback, 2026-09-03:

- PLATEAU-Terrain was removed from the default viewer after the live map check showed visible height mismatch.
- The default viewer uses Cesium's ellipsoid globe again for stable presentation alignment.
- The PLATEAU building tileset offset is `-36 m` for rendering only.
- GSI DEM5A remains the numeric source for water-depth and candidate-location calculations.

## Runtime architecture

- `src/data/groundElevation.ts` owns PNG decoding and numeric lookup.
- Valid elevations are held in `Float32Array` tiles and exposed through `sampleMeters(lon, lat)`.
- `src/cesium/groundElevationLayer.ts` derives a raster color layer from the same numeric data.
- Cesium receives nine imagery layers; there are no elevation Entities and no React component per cell.
- React owns only the ON/OFF state, loading/error state, legend, and provenance copy.
- Future inundation code should call the ground-elevation data API and use orthometric tide levels in the same vertical reference.
